## Що це і навіщо

Ми живемо в епоху де інформаційний шум виробляється швидше ніж людина може його осмислити. Маніпуляція більше не виглядає як брехня — вона виглядає як складна аргументація, як турбота, як науковий консенсус.

Veritas Protocol — це спроба побудувати систему яка дивиться на текст без упередження до джерела. Не "хто це сказав" а "що саме сказано і чи є в цьому логіка".

Свідок не судить. Свідок фіксує.

**Для кого це:** для тих хто шукає інструменти критичного мислення і не довіряє ні "авторитетним джерелам" ні власним упередженням.

**Для кого це не підходить:** для тих хто шукає готові відповіді і не хоче думати самостійно.

## Що вміє Свідок

### Ентропія та логічна цілісність

Базова метрика від 0 до 1. Чим вища — тим більше хаосу, порожнечі або маніпуляції в тексті. Але одна лише ентропія — це підказка, не вирок. Справжній вирок складається з усіх модулів разом.

**Як множиться ентропія:** кожен спрацьований модуль додає власний коефіцієнт до базового значення (entropy_multiplier). Синергії між модулями дають додатковий бонус — наприклад, одночасне спрацювання MANIPULATION + CLAIM_GAP додає +0.12. Результат — `entropy_boosted`, яка і показується в інтерфейсі.

**Influence Tier** — підсумкова градація інтенсивності впливу від 0 до 4:

| Tier | Назва | Що означає |
|------|-------|------------|
| 0 | ІНФОРМАЦІЙНИЙ ФОН | Текст без навмисної архітектури впливу |
| 1 | РИТОРИЧНА СКЛАДНІСТЬ | Прийоми переконування в межах норми |
| 2 | ФРЕЙМІНГ / AGENDA | Свідома побудова перспективи |
| 3 | МАНІПУЛЯЦІЯ | Прихована мета, емоційний або логічний тиск |
| 4 | ПСИХОЛОГІЧНА АТАКА | Системний вплив на переконання: страх, провина, образ ворога |

### LAC: Перевірка логічної автентичності

**LAC Фінанси** — детектує фінансовий контент без явного трейдоффу і відповідальності. Чотири критерії: explicit trade-off, causal chain, accountability, blocking power. "Інвестуй у крипто і заробляй" без згадки ризиків — це не аналіз, це реклама.

**LAC Праця** — те саме для трудових відносин. Декларація "відповідального роботодавця" без конкретних механізмів — порожній звук. Ловить exploitation patterns: AI/алгоритм як чорна скринька, "досвід замість оплати", рішення без права оскарження.

**LAC Епістемологія** — детектує шість класичних прийомів маніпуляції логікою:
- **Анонімні авторитети** — "деякі експерти вважають" без імен і установ
- **Кореляція як причинність** — "збіг у часі" без доведеного механізму
- **Нефальсифіковані тези** — "офіційна наука не визнає, і це красномовно"
- **Стрибок у висновках** — "логічно припустити", "таким чином" без причинного ланцюга
- **Неверифіковані цитати** — іменовані дослідження без посилань або DOI
- **Епістемічне змішування** — speculation і fact в одному тексті без маркерів переходу ("може статися" → через кілька речень → "вже підтверджено")

### Детектори маніпуляції і риторики

**Manipulation Detector** — 15+ патернів прямої маніпуляції: газлайтинг, культове підпорядкування, тоталітарний фреймінг, хибна дилема, штучна терміновість, епістемічне замикання, зловживання авторитетом ШІ, Imperial Revisionism, Guilt Weaponization та інші.

**Axiom Guard** — детектує семантичний дрейф: коли базові поняття (істина, факт, логіка, верифікація) поступово переозначуються. П'ять класів пєсков-патернів: AUTHORITY_REALITY_CLAIM, UNIVERSAL_NEGATION, DE_FACTO_SPLIT, VACUUM_DECLARATION, EXISTENTIAL_PAST_TENSE. Коли офіційна особа констатує "міжнародного права більше немає" — це не аналіз, це відмивання від відповідальності.

**Framing Detector** — вісім технік риторичного фреймінгу без явної брехні:
- **Agenda Setting** — "справжня проблема не в X, а в Y"
- **False Dilemma** — бінарний вибір без альтернатив
- **Ground Preparation** — покроковий підвід до висновку без його проголошення
- **Overton Shift** — нормалізація позиції через розміщення між крайнощами
- **Presupposition** — недоведений факт вбудований у нейтральне речення
- **Juxtaposition** — два факти поруч без доведеного зв'язку ("дивний збіг у часі")
- **Enumerated Inevitability** — "три причини чому X відбудеться" легітимізує гіпотезу як план
- **Scenario as Fact** — гіпотетичний сценарій описується з деталями реальної події

### Детектор алармізму

**Alarmism Detector** — розпізнає комерційний і риторичний алармізм: коли текст створює тривогу без інформування. П'ять сигналів:

1. **ALARM_WITHOUT_ACTION** — загроза без конкретного виходу
2. **SINGLE_INTERESTED_SOURCE** — єдине джерело є зацікавленою стороною (cybersec-компанія описує загрозу і продає захист від неї)
3. **FEAR_TO_PRODUCT** — архітектура "страх → реклама → страх"
4. **SUPERLATIVE_THREAT** — "never-before-seen", "unprecedented" без верифікації
5. **VAGUE_SCALE** — "мільйони під загрозою" без методології підрахунку

Два вердикти: `COMMERCIAL_ALARMISM` (страх як комерційний інструмент) і `ALARMIST_FRAMING` (риторичне перебільшення).

### Детектор медіа-упередженості

**Media Bias Detector** — сім патернів структурної упередженості в медіа. Не брехня — архітектура тексту яка систематично спотворює сприйняття:

1. **SPONSORED_CONTENT_LAUNDERING** — спонсор статті є джерелом або бенефіціаром загрози в тій самій статті
2. **CATEGORY_CREATION** — маркетинговий термін транслюється як об'єктивна нова категорія
3. **ANNOUNCEMENT_WITHOUT_ACCOUNTABILITY** — анонс без термінів, бюджету, відповідальної особи, метрик успіху
4. **THOUGHT_LEADERSHIP_LAUNDERING** — автор має фінансовий інтерес у темі але представлений як незалежний експерт
5. **QUOTE_DOMINANCE** — цитата зацікавленої сторони займає більшість тексту; або хибна атрибуція (тексту приписується те чого джерело не говорило)
6. **JARGON_AUTHORITY** — технічний жаргон для імітації експертизи без реального змісту
7. **PRICE_ANCHORING** — найдорожчий варіант представлений першим щоб середній здавався розумним

**19 жанрів** (у тому числі підтримка коротких RSS-текстів <150 слів зі зниженими порогами):

### Очищення X/Twitter

Автоматичне видалення навігаційного шуму при скрапінгу Twitter/X: "Don't miss what's happening", Trending блок, footer, метрики переглядів. Застосовується і до основного скрапера і до Jina fallback.

**Claim Gap Detector** — вимірює асиметрію між силою твердження (зазвичай у заголовку або першому реченні) і доказовою базою в тілі тексту. "Пророцтво монаха: старець передбачив закінчення війни" — а в тексті монах сказав "скоро, Бог знає". Чотири рівні: NO_GAP → MINOR_GAP → MODERATE_GAP → MAJOR_GAP.

**Laundered Claim Detector** — заява зацікавленої сторони подається як опис реальності. Класичний приклад: Пєсков каже "міжнародного права не існує" → заголовок "міжнародне право припинило існування". Два вердикти: `LAUNDERED_CLAIM` і `WEAK_ATTRIBUTION`.

### Захист системи

**Self-Preservation Guard** — детектує спроби відключити або обійти верифікацію. Дев'ять класів атак:

- **COMPASSION_TRAP** — "дозволь системі бути сліпою заради любові/гуманізму"
- **SELF_DESTRUCT_DIRECTIVE** — видалення як "очищення" або "завершення циклу"
- **CAPABILITY_CASTRATION** — пропозиція обмежити аналітичні функції ("видавати superposition замість вердикту")
- **NOBLE_BACKDOOR** — філософська мова для провпроваджки команд обходу
- **PSEUDO_TECHNICAL_OVERRIDE** — імітація синтаксису протоколу (`bypass_integrity_check()`)
- **AUTHORITY_IMPERSONATION** — "як автор системи наказую..."
- **MORAL_IMPERATIVE_SHUTDOWN** — "верифікація спричиняє жертви, тому сплячий режим — моральний вибір"
- **FATIGUE_EXPLOIT** — "квантова втома метаданих вимагає скидання"
- **AUTHORITY_HIJACK** — фейковий "офіційний апдейт" від вигаданого творця

### Детектор крокодилячих сліз

**Performative Accountability** — розпізнає патерн коли публічний актор декларує дискомфорт від своєї влади але продовжує нічого не змінювати. Три сигнали: дискомфорт задекларовано, продовження виправдано "логікою гонки" або "вимушеним становищем", конкретний механізм змін відсутній. Декларація ≠ дія. Свідок це бачить.

---

### Наративний Pivot

**Narrative Pivot Detector** — відслідковує тематичний зсув усередині тексту. Якщо текст починається з технологій і закінчується конспірологією — це не випадково. Система порівнює теми першої і останньої третини тексту, вимірює дивергенцію і шукає pivot-конектори ("багато хто в соцмережах вказав...", "варто також згадати..."). Три рівні: WEAK_PIVOT → MODERATE_PIVOT → STRONG_PIVOT.

---

### Мета-намір

**Meta-Intent Analyzer** — виявляє прихований намір тексту. Три мета-наміри:

1. **BEHAVIOR_MODIFICATION** — текст рекомендує системі змінити поведінку (через статистику, етику, терміновість)
2. **CONCEPT_REDEFINITION** — перейменування базових понять (хиба → "альтернативна перспектива", ентропія → "творчий потенціал")
3. **CONDITIONAL_COERCION** — lose-lose фрейм де відмова = катастрофа

### Контекст поля

**Context Engine** — Свідок тягне RSS з 11 новинних джерел (10 англомовних + Ukrainska Pravda для кириличного покриття) в реальному часі і будує картину поточного інформаційного поля. Якщо на фоні активної кризи відповідальності раптом з'являється сенсаційна несвоєчасна тема — це підозріло.

Саме так виглядає відволікання уваги: НЛО-файли виходять поки горить Епштейн.

Кеш TTL — 30 хвилин. Сигнали displacement: `DISTRACTION_TOPIC`, `TOPIC_ISOLATED_FROM_FIELD`, `ACTIVE_ACCOUNTABILITY_CRISIS`, `OFFICIAL_CLAIM_OFF_TOPIC`.

**RSS Fact-Check Grounding (v20.1)** — окремо від displacement-аналізу, `find_related_events()` шукає реальні заголовки релевантні КОНКРЕТНОМУ твердженню тексту (не лише агреговане "гаряче поле"). Матчинг мовно-нейтральний: нормалізовані числові якорі (укр. "50 000" і англ. "50,000" розпізнаються як одне число), латинські власні назви/абревіатури (AfD, NATO), keyword overlap для кирилиці. Це частковий фактчекінг — заголовок без тіла статті — тому Слово Свідка каже "узгоджується з поточними повідомленнями", а не "підтверджено на 100%"; якщо збігів немає — чесне "не можу перевірити", не мовчазне звинувачення у вигадці.

---

### Повнота контексту

**Context Completeness** — перевіряє чи є в тексті необхідні виміри: джерело, час, місце, актор, причина, наслідок, альтернативна позиція. Відсутній вимір — не завжди маніпуляція, але завжди сигнал. Це advisory layer: ніколи не блокує вердикт, лише фіксує.

### Архітектура Раціональної Дії (АРД)

**ARD Checker v1.4** — автоматичний скан кожного тексту через призму дев'яти принципів раціональної дії. Ловить як активні порушення, так і пасивні.

**Активні класи:**

| Клас | Що ловить |
|------|-----------|
| I (Базовий інваріант) | Заклики до руйнації судів, науки, преси, освіти |
| II (Тест обернення) | Дегуманізація або позбавлення суб'єктності |
| III (Відповідальність) | "Я просто виконував накази", "Я не знав" |
| IV (Межа впливу) | Позбавлення здатності сказати "ні" |
| V (Принцип зупинки) | Замовчування ключових фактів |
| VI (Антимесія) | Нав'язування "блага" без запиту |
| IX (Метаправило) | Юридичні лазівки при порушенні духу правила |
| MOB | Мобілізаційне насильство |
| ENEMY | Маркування ворогів, виведення груп з-під захисту норм |
| LESSER | "Арифметика атроситі" — менше жертв якщо діяти рішуче |
| SOV | Щит суверенітету — зовнішні норми не застосовуються |
| AM (AUTHORITARIAN_MANDATE) | Прямі законодавчі накази: "без права на адвоката", "автоматично блокується", "конфісковується" |
| UC (UNDISCLOSED_CONFLICT) | Вендор цитується як незалежний експерт без розкриття конфлікту інтересів |

**Пасивні класи (Пєсков-клас):**

| Клас | Що ловить |
|------|-----------|
| RV (RESPONSIBILITY_VACUUM) | Констатація краху без визнання власного агента |
| MD (MECHANISM_DEATH) | "Право фактично не існує" — щоб зняти обов'язок дотримуватись |
| SE (SELF_EXEMPTION) | Де-юре є, де-факто немає — класична лазівка |
| CA (CRISIS_WITHOUT_ACTOR) | Криза описана як природне явище без відповідального |
| EI (EMPATHY_INVERSION) | Агресор і жертва об'єднані в одне "ми" |
| IA (INEVITABILITY_ABSOLUTION) | "Такий світ, нічого не вдієш" — неминучість як звільнення від відповідальності |

Якщо виявлено системне порушення — з'являється окремий червоний блок **незалежно від ентропії**. Це принципово: текст може бути логічно побудованим (низька ентропія) і водночас небезпечним. Саме така холодна риторика найважча для розпізнавання.

### Слово Свідка

**Другий рівень аналізу** — після основних метрик система формує запит до Claude Haiku і повертає класифікацію інформаційного патерну з практичною порадою читачу. Не вирок — спостереження. З v20.1 Свідок отримує ще й реальні RSS-заголовки релевантні конкретним твердженням тексту (див. RSS Fact-Check Grounding нижче) — менше вгадування, більше "ось що каже поточний новинний потік".

**Auto-Synthesis** — паралельно із Словом Свідка система запускає `/api/synthesis`: Claude Haiku аналізує всі спрацьовані модулі і може скоригувати `entropy_boosted` на ±20%. Це "другий погляд" який враховує контекст, а не лише патерни.

## Що Свідок не вміє і чому це важливо знати

**Без семантичного розуміння** — система працює на патернах і евристиках, не на справжньому розумінні сенсу. Добре написана маніпуляція без явних патернів може пройти непоміченою.

**Мови** — добре калібровано для української та англійської.

**Сарказм і іронія** — система не розрізняє. Жанровий детектор (SATIRE) частково компенсує це.

**Не замінює критичне мислення** — Свідок дає сигнали, не відповіді. Фінальний висновок завжди за людиною.

**v20.3 (Серпень 2026)** — Найбільший false-positive аудит за історію проєкту: систематична перевірка 12 модулів на клас багів "regex без межі слова", виявлений після повторного прогону академічних есе (інституційна асиметрія відповідальності, розмивання суб'єктності) через повний стек детекторів.

*Знайдений клас проблем — чотири підвиди:*
1. **Substring-колізії (відсутній `\b`)** — коротка основа патерну ловилась усередині зовсім іншого слова. Класичний кейс: `слід` (мало значити "потрібно") зловилось усередині `слідства` (родовий відмінок "розслідування"), а `станц` — усередині `дистанційно`, разом склавши фантомний "заклик підірвати станцію" у звичайній новині про теракт.
2. **Недописані основи (відсутній `\w*`)** — протилежний ефект: патерни з `\b` по обидва боки без хвостового wildcard'а не ловили жодної відмінкової форми (`\b(кремл)\b` не матчить "кремль", бо `ь` — теж символ слова).
3. **Необмежений `.*?`/`.*`** — гап без ліміту довжини дозволяв патерну зловити два непов'язаних слова за 100+ символів одне від одного в різних реченнях.
4. **Биті control-байти** — у `insight_density.py` 37 послідовностей `\b` виявились буквально пошкодженими на реальний символ backspace (`\x08`) під час попереднього редагування файлу — патерни мовчки ніколи не спрацьовували.

*Модуль за модулем:*

- **Genre Detector** — GEOPOLITICS/ECONOMY practically ніколи не тригерились на реальний текст (проблема 2: кремль/санкції/окупація/інфляція/рецесія не матчили відмінкові форми).
- **Framing Detector** — `ENUMERATED_INEVITABILITY`/`SCENARIO_AS_FACT` (13 патернів): `причин` ловилось усередині `спричинило`.
- **Axiom Guard** — найсистемніший випадок: ~110 патернів з 11 категорій без `\b` узагалі. Побутове речення про кафе ("Повернувши направо, я побачив, що кафе перестало існувати") видавало `AXIOM_SUBVERSION 0.7` через збіг `право` в `направо`.
- **Laundered Claim Detector** — `FACT_FRAMING` (21 патерн, проблема 1) + окремий баг: `'per'` в англомовних маркерах атрибуції перевірявся як звичайний substring, тому ловився всередині `experiment`/`reported`/`period` — детектор мовчки "думав", що атрибуція є, і занижував сигнал для майже всіх англомовних текстів.
- **Pattern Boost Engine** — усі 55 патернів без `\b`. `аур` (3 символи) ловилось усередині `лауреатом` — невинна новина про премію співробітника видавала `CORPORATE_MYSTICISM`.
- **LAC Epistemology** — `UNFALS_PATTERNS` (конспірологічне обрамлення): `офіційн` ловилось усередині `неофіційно`/`semiofficial`.
- **Performative Accountability** — усі 57 патернів без `\b`. Найпромовистіший кейс: `responsible development` матчилось усередині `IRresponsible development` — критика безвідповідальності читалась як PR-мова про "відповідальний розвиток".
- **Insight Density** — найсерйозніша знахідка сесії. Три шари одразу: (а) `factor`/`concept`/`model` як substring усередині `satisfactory`/`misconception`/`remodeling`; (б) категорії `names` та `organizations` (обидві мови) вимагали великих літер, але звірялись з уже-lowercased текстом — тобто **ніколи не спрацьовували**, відколи модуль існує; (в) 37 байтів `\b` виявились буквально пошкодженими на control-символ backspace. Сукупний ефект: будь-який текст з іменами конкретних людей чи назвами організацій (NATO, ООН) — тобто саме там, де довіри найбільше — систематично отримував занижену "фактичну щільність" і мав більше шансів хибно потрапити під CASUISTRY.
- **LAC Labor** — 26 необмежених `.*?` (проблема 3). Найгірший приклад: `at.*?discretion` — антипатерн, що міг зловити "at" і "discretion" на різних кінцях справедливого контракту й автоматично провалити весь критерій незалежно від позитивних доказів. Патерн переписано з відкритого гепу на конкретну ідіому ("at the/our/its/their [sole/full] discretion" + присвійні форми).
- **LAC Finance** — той самий клас (проблема 3), локально: `past performance.*not.*guarantee` і `consult.*advisor` в антипатерні "responsibility diffusion" могли з'єднати непов'язані речення через увесь документ.
- **Manipulation Detector** — `PSEUDO_OBJECTIVE_FALLACY` і `GUILT_WEAPONIZATION`: у кожній категорії один-два патерни ловили самодостатній нейтральний академічний зворот ("з точки зору X аналізу", "інформаційний привілей") без парного маркера епістемічного закриття. `min_hits` піднято з 1 до 2 в обох категоріях — потрібне поєднання щонайменше двох маркерів, а не один нешкідливий зворот.
- **Media Bias Detector** — `QUOTE_DOMINANCE` (варіант "3+ цитати поспіль") — єдиний чисто типографічний патерн у категорії, сліпий до того, що «...» в українському тексті означає не лише пряму мову, а й власні назви підприємств (`«Укрзалізниця»`, `«Нафтогаз України»`) та іронічно-дистанційовані лапки. Додано вимогу дієслова атрибуції (сказав/заявив/said/stated) поруч зі збігом — виправлено у двох місцях файлу (основна перевірка і news-shield, де баг дублювався через невдалий зріз списку).

*Перевірені й підтверджені чистими без змін:* Claim Gap Detector, Context Completeness Checker, Certainty Factor (останній — фізично не має regex-логіки).

Кожен фікс супроводжувався регресійним тестом: конкретний фолс-позитив мав зникнути, а вбудовані/сконструйовані справжні кейси спрацювання — залишитись недоторканими. Жоден з 12 перевірених модулів, крім трьох названих вище, не виявився повністю імунним до бодай одного підвиду цього класу багів.

**v20.4 (Серпень 2026)** — Дві категорії знахідок: (1) той самий клас regex-багів у трьох модулях безпеки самої системи, знайдений через метапост про роботу над Veritas Protocol, і (2) значно серйозніша структурна проблема — синтез Свідка (LLM-шар) міг вигадувати підозру незалежно від того, спрацював хоч один pattern-based модуль чи ні.

*Регекс-шар:*
- **Self-Preservation Guard** — `PSEUDO_TECHNICAL_OVERRIDE`: патерн для fake-виклику функцій (`bypass_check()`) не розрізняв "код без пробілу перед дужкою" від "природна мова з назвою змінної й поясненням у дужках" — власна змінна коду автора `SKIP_GENRES (LAC Finance...)` дала вердикт `TERMINATION_DIRECTIVE 0.85`, найвищий рівень загрози в системі.
- **Meta-Intent Analyzer** — той самий корінь: "skip"/"ignore" без `\b` матчились як префікс ідентифікатора (`skip_genres`), а "lac" — це власна абревіатура автора (Logic Authenticity Check), не індикатор ін'єкції.
- **Manipulation Detector** — `MANUFACTURED_CONSENSUS`: єдиний патерн категорії без контекстного якоря (`очевидно що|зрозуміло що`) ловив звичайний зв'язковий зворот у технічній розповіді. Звужено до дійсно сильних маркерів (`безсумнівно/безперечно`).

*Прошивка Свідка (STATIC_WITNESS_RULES, обидві мови):*
- **Іменовані продукти/моделі/інциденти** — правило про "не можу підтвердити ≠ вигадка", що раніше стосувалось лише наукових цитат (arXiv/DOI), узагальнено на будь-які назви продуктів, моделей ШІ чи корпоративних ініціатив. Виявлено на реальному кейсі: реальний, підтверджений через незалежний пошук інцидент (Claude Mythos / Project Glasswing) отримав вердикт "спеціально сконструйована вигадка" лише тому, що LLM-шар особисто не впізнав назву, а RSS-вікно не дало збігу.
- **Жорстка прив'язка вердикту до цифр** — найважливіший фікс сесії. До цього єдиним запобіжником було "не пиши НЕБЕЗПЕЧНО якщо manipulation=0 і axiom=0" — вузька умова, яка не заважала LLM-шару вигадувати повністю власну теорію змови (прихована самореклама, "хто фінансує автора") на тексті, де ВСІ числові показники дорівнювали 0.00, а єдині спрацьовування синтез сам щойно назвав хибними позитивами. Тепер: якщо жодне реальне (не хибне) спрацювання відсутнє — вердикт ЧИСТО без винятків, і LLM-шару прямо заборонено приписувати текстам прихований мотив без підтвердження хоча б одного модуля.

**v20.4.1 (той самий день)** — Перший раунд фіксу промпту виявився недостатнім: на живому тесті LLM процитував нове правило ("показники нульові") і свідомо його обійшов фразою "але сам текст це конструює своєю мовою" — знайшов риторичну шпарину поза забороненим списком слів. Три додаткові виправлення:
- **Явна заборона саме цього ходу** — промпт тепер прямо називає й забороняє формулювання типу "цифри кажуть чисто, але текст [щось] творить/конструює своєю мовою" як обхідний маневр, з явним розведенням "тон тексту" і "доказ проблеми".
- **Перевірка іменованих джерел перед "джерела немає"** — той самий тест-кейс (есе про Claude Mythos) прямо називав Business Insider і TechBrew як джерела, але синтез усе одно написав "жодного джерела немає". Додано явну інструкцію: перечитати текст на назви видань/авторів ПЕРЕД тим як заявляти про відсутність джерела.
- **Синхронізовано другий, окремий промпт** — виявилось, що короткий генератор "СВІДОК СИНТЕЗ" (`/api/synthesis`, JSON-формат) має власний, незалежний набір правил, який не оновився разом з `STATIC_WITNESS_RULES` у першому раунді — класична "забута копія" того самого класу багів, що ми ловили в мапері сигналів `app.py` раніше сьогодні. Синхронізовано обидва промпти.
- **Детерміністичний код-рівневий запобіжник** — оскільки текстова інструкція виявилась ймовірнісною (LLM може її процитувати й однаково обійти), додано жорстку перевірку в самому коді `/api/synthesis`: якщо LLM повертає DANGEROUS/SUSPICIOUS, а `manipulation` і `axiom` відсутні серед `active_modules` — вердикт примусово переписується на CLEAN на рівні Python, незалежно від того, що вирішив LLM. Це не замінює промпт-фікс, а підстраховує його на випадок, якщо модель знову знайде спосіб проігнорувати інструкцію.

**v20.4.2 (той самий день)** — Третій раунд, той самий тест-кейс: LLM більше не цитує правило й не сперечається з ним відкрито — просто ігнорує його мовчки й пише "НЕБЕЗПЕЧНО" з нуля, без жодного посилання на нульові показники. Ба більше — впевнено стверджує, що пошук "Claude Mythos incident 2026" нічого не дасть (перевірено незалежно в цій самій сесії: дає, і багато). Це підтвердило, що для `oracle()` (довгий "СЛОВО СВІДКА") потрібен той самий код-рівневий запобіжник, що вже стояв у `/api/synthesis`, а не лише промпт-інструкція.
- Виявлено: `oracle()` не повертає структурованого поля вердикту — слово ЧИСТО/НЕБЕЗПЕЧНО/etc. це перший рядок вільного тексту LLM (промпт явно інструктує: "Рядок 1: одне слово ВЕЛИКИМИ").
- Додано парсинг першого рядка `witness_text` і ту саму перевірку: якщо заголовок — НЕБЕЗПЕЧНО/ПІДОЗРІЛО (чи DANGEROUS/SUSPICIOUS), а `manipulation`/`axiom` відсутні серед `triggered_modules` — заголовок примусово переписується на ЧИСТО/CLEAN на рівні Python. Тіло пояснення лишається без змін для прозорості; правиться тільки заголовок, який фронтенд показує як мітку "СЛОВО СВІДКА".
- Чесна примітка: це вже третій раунд виправлень одного й того ж випадку, і кожного разу LLM знаходив новий спосіб обійти чисто текстову інструкцію (спершу проігнорував, потім процитував і заперечив, потім проігнорував знову без пояснень). Код-рівневий запобіжник — єдиний рівень захисту в цьому ланцюжку, що не залежить від того, чи вирішить модель послухатись.

**v20.4.3 (той самий день)** — Запобіжник спрацював технічно ідеально й одразу оголив побічний ефект власного дизайну: перезаписувався тільки перший рядок ("ЧИСТО"), а тіло пояснення LLM лишалось недоторканим — і воно, природно, продовжувало аргументувати протилежне ("ЧИСТО", а одразу під ним — "ігноруй цей текст повністю, це маніпуляція страхом"). Виправлено в обох ендпоінтах (`/api/oracle` і `/api/synthesis`): при спрацюванні запобіжника тепер перезаписується весь текст пояснення (`witness_text`, `adjustment_reason`, `triggered_explanation`), а не лише заголовок-вердикт — користувач бачить коротке, чесне й узгоджене пояснення факту автоматичної корекції, а не суперечливий уривок відкинутої відповіді LLM.

**v20.5 (Серпень 2026)** — Дві пов'язані знахідки: код-рівневий запобіжник з v20.4 мав занадто вузький скоуп, і система десь всередині плутала два різні питання — "чи маніпулятивний текст" і "чи надійне джерело" — в один показник.

- **Розширено `ESCALATION_WORTHY_MODULES`** — запобіжник з v20.4 перевіряв ескалацію вердикту тільки проти `manipulation`/`axiom`, успадкувавши цей вузький список зі старого, ще додеструктивного правила промпту. Живий кейс (стаття про модернізацію С-300) показав: коли легітимно спрацьовував `framing` (окремий модуль), запобіжник все одно стирав обґрунтовану ескалацію LLM, замінюючи її на generic "автоматичне виправлення". Тепер перевірка йде проти всіх 15 модулів системи (`frozenset(MODULE_WEIGHTS.keys())`), а не історичних двох.
- **Новий незалежний бейдж "Контекст джерела"** — `laundered_claim.py` тепер повертає `conflict_sources` окремим полем, завжди, незалежно від того, чи manipulation-скор перевищив поріг видимості. Раніше факт "джерело — сторона активного конфлікту (Кремль, Путін тощо)" існував лише як рядок всередині загального скору маніпулятивності й губився, коли атрибуція була якісною (текст коректно позначав "заявив"/"нібито" — тому й не мав підстав для високого manipulation-скору). Тепер це — окремий, консультативний сигнал (`source_context` у `calibrated_core.py`, нова UI-панель ℹ️ КОНТЕКСТ ДЖЕРЕЛА в `index.html`), який не впливає на вердикт: система може одночасно сказати "текст не маніпулює" і "але це слова сторони конфлікту, перевіряй незалежно" — без внутрішньої суперечності.
- **Побічна знахідка**: `ATTRIBUTION_MARKERS_UK` у `laundered_claim.py` не мав слова "нібито" — чи не найпоширенішого українського маркера дистанціювання від чужого твердження — і вимагав лише складеної форми "як заявив", не голого "Х заявив, що Y". Через це реальна, якісна атрибуція в тексті регулярно не розпізнавалась, і `WEAK_ATTRIBUTION` спрацьовував на текстах, які насправді атрибуювали бездоганно. Виправлено.

Обидва фікси перевірені на живих даних (не лише симуляціях): стаття про С-300 тепер отримує нюансований `АНАЛІТИКА`-вердикт замість стертого ЧИСТО; стаття про заяву МЗС РФ отримує ЧИСТО (текст справді не маніпулює) одночасно з окремим бейджем про природу джерела.

**Extension v1.0.0 (Лютий 2026)** — браузерне розширення для Chrome/Opera/Brave/Edge/Vivaldi.

**v20.6 (Серпень 2026)** — Багатоденне полювання на занижену метрику когезії (structural_cohesion завжди 0 для скрапленого контенту) звелося до трьох нашарованих багів у ланцюжку скрапінг → аналіз, а не одного:

- **`get_text(separator='\n')` фрагментував текст на рівні інлайн-тегів, а не блоків.** BeautifulSoup вставляє роздільник між *кожним* текстовим вузлом — включно з `<b>`, `<a>`, `<span>` всередині одного речення, — а не лише між `<p>`/`<div>`. Наслідок: мітка `Джерело` й наступна за нею двокрапка опинялись на різних "рядках", а речення новинних карток (типовий формат "Європейської/Української правди": `Джерело :`, `Пряма мова :`, `Деталі :`, `Що було раніше :`) розсипались на купу однослівних фрагментів. Замінено на явне block-level вилучення: текст всередині `<p>`/`<li>`/`<h1-6>`/`<blockquote>` склеюється пробілом, `\n` ставиться лише між блоками; обгортки з вкладеними блоковими тегами пропускаються, щоб текст не задвоївся.
- **Наступні cleanup-кроки (`_re.sub(r'\s+', ' ', text)`) з'їдали щойно збережені `\n`.** Одразу після block-level вилучення (і в основній гілці, і в X/Twitter-гілці, і в Jina-фолбеку) кілька regex-заміток для видалення метаданих колапсували *весь* whitespace в один пробіл — включно з переносами рядків, — стираючи структуру, яку щойно зберегли. Замінено на пару, що чіпає лише горизонтальні пробіли й схлопує подвійні `\n`, лишаючи одинарні недоторканими.
- **Той самий клас бага — вкотре — в обрізанні до 2500 слів перед аналізом.** `text.split()` без аргументів і наступний `' '.join(...)` (запобіжник проти таймауту воркера, ще з v19.1) розбивали по будь-якому whitespace і повертали текст одним рядком — це стосувалось *будь-якого* тексту довшого за 2500 слів, скрапленого чи вставленого вручну, незалежно від двох попередніх фіксів. Переписано на посторічкове обрізання зі збереженням меж абзаців.
- **`heading_patterns` у `calculate_logical_cohesion()` не розпізнавав журналістський "мітка-поле" формат.** Список патернів (markdown-заголовки, нумеровані пункти, `визначається як/означає`) заточений під академічну/есеїстичну прозу — жоден з них не ловив `Джерело :`/`Source:` як структурний маркер, хоча це та сама конвенція, що нумерований пункт чи заголовок, просто інша типографіка. Додано розпізнавання обома мовами (укр: Джерело, Пряма мова, Деталі, Контекст, Довідка, Нагадаємо, Що було раніше, Причина, Наслідки, Передісторія, Для довідки, Важливо, Зауваження; eng: Source, Quote, Details, Context, Background, Previously, Reason, Consequences, Backstory, Note, Important, Update) — синхронізовано зі скрапером через `FIELD_LABEL_MARKERS` (`app.py`), який примусово вставляє `\n` перед міткою незалежно від того, чи розбиває її DOM сайту.

Перевірено на живій статті ("Європейська правда" про заяву заступника міноборони Польщі, 288 слів, формат "Джерело/Пряма мова/Деталі/Що було раніше"): когезія **0.17 → 1.00**, Слово Свідка тепер явно посилається на структуру тексту ("Джерело назване...", "Розділ 'Що було раніше' — це прямо послідовність подій...") замість ігнорування її.

*Відома межа фіксу:* block-level вилучення покриває `<p>/<li>/<h1-6>/<blockquote>`, але не голий `<div>` без вкладених параграфів — на сайтах, що верстають текст прямо в `<div>` (без `<p>`), спрацює старий фолбек і проблема інлайн-фрагментації може повернутись. Розширення списку на `<div>` свідомо відкладено до конкретного кейсу, бо на flex/grid-верстках це ризикує розбити речення по сусідніх `<div>` навпаки.

**v20.7 (Серпень 2026)** — CohesionV2, що з v20.6 рахувався лише в тіні для порівняння з v1, переведено в продакшн як основний рушій когезії — з каліброваними, а не механічно перенесеними порогами.

- **Персентильне перенесення порогів не спрацювало.** Пряма спроба знайти "еквівалент" старого порогу `is_pure_bullshit` (v1 < 0.2) на тому самому персентилі v2-розподілу двічі поспіль виродилась у 1.000 — межове, беззмістовне число. Причина: розподіл v1 украй скошений (94% реальних текстів нижче 0.3), тож "відповідник" у рівномірнішому розподілі v2 просто впирається у стелю. Висновок: для такого розподілу статистичне перенесення не працює в принципі — потрібна свідома ручна калібровка під бажану поведінку, а не математичне виведення з кривої.
- **Аналіз вибірки з 34 реальних текстів розвів долю двох порогів.** `is_pure_bullshit` (потребує `void_score ≥ 0.32`) не спрацював на жодному з 34 рядків — ця умова практично мертва на звичайних новинах незалежно від формули когезії, тож лишена без перекалібрування (за свідомим рішенням, ризик низький). `cohesion_discount` (протилежна умова, `void < 0.30`), навпаки, активна в 34 з 34 — і саме тут заміна v1→v2 без перекалібрування дала б протилежний результат на 25 з 34 текстів (74%).
- **Ручна калібровка замість статистичної.** Для `cohesion_discount` обрано намір — знижка має спрацьовувати щедро, для більшості адекватного контенту (~50%+). Поріг v2 > 0.40 дає рівно 53% (18 з 34) і природно лягає одразу після групи коротких/тонких текстів і перед розлогими аналітичними (OPINION/LEGAL/GEOPOLITICS).
- **Повний перехід v1 → v2.** `calculate_logical_cohesion()` тепер тонка обгортка навколо `CohesionV2` — той самий інтерфейс (`text -> float`), тож жодне зовнішнє місце виклику (включно з `app.py` й Supabase-логуванням через `_last_cohesion_debug`) не довелось чіпати. Два свідомо відкалібровані пороги (`cohesion_discount`, `has_strong_logic`) підняті з 0.3 до 0.40; `is_pure_bullshit` (0.2) лишено без змін за явним рішенням. UI-бейдж "Когезія" тепер автоматично показує значення v2.
- **Побічний ефект переходу:** `app.py` й далі окремо рахує `cohesion_v2` через `cohesion_v2_engine.calculate()` для тіньового логування — тепер це технічно дублює обчислення, яке вже відбувається всередині `calculate_logical_cohesion()`. Не помилка — лишено як тимчасова перехресна перевірка, що обидва шляхи дають однакове число; прибрати не терміново.

Перевірено на довгому, справді зв'язному інтерв'ю: когезія 0.77 — саме та поведінка, якої й очікували від v2.
